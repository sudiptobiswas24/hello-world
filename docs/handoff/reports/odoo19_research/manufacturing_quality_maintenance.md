# Odoo 19 Manufacturing, Quality, Maintenance and PLM compared with this ERP's production, "how it's made", plant and quality modules

Scope: Odoo 19.0 Manufacturing (BoM, routings, work orders, Shop Floor, MPS, subcontracting, unbuild, scrap), Quality, Maintenance, PLM, Repairs and the IoT parts that touch production, set against `/home/user/hello-world` (read only). Reference version is 19.0; items found only for 18 or earlier are marked.

How to read the tables below (applies to every table in Key question 1):
- **New in 19**: `Y-code` = confirmed by diffing the 18.0 and 19.0 branches of the Community source; `Y-doc` = the 19.0 documentation page differs from 18.0 but the code was not diffed (Enterprise code is not public, and docs sometimes lag code); `N` = no change evidenced (docs page identical, or code identical); `?` = cannot be told.
- **Ed.**: `C` = Community (module exists in the odoo/odoo 19.0 tree); `E` = Enterprise (inferred: no such module in the Community tree, and Community settings show it with the `upgrade_boolean` widget).
- **ERP**: `have` / `partial` / `missing`, with the file that is the evidence. Paths are under `/home/user/hello-world/`.
- **Rel**: relevance to a woven polypropylene sack plant in India. `G` = needed before go-live, `S` = soon after, `L` = later or not relevant. One-line reason.

## 1. What does Odoo 19 offer in Manufacturing, Quality, Maintenance, PLM, Repairs and production IoT, and which edition is each part in?

### Takeaway
Odoo 19 Community carries the core of manufacturing (BoMs, kits, by-products, operations, work centres, work orders, MO costing, subcontracting, unbuild, scrap, repairs, a basic maintenance app); Shop Floor, MPS, Quality, PLM, IoT and the work-centre-to-equipment link are Enterprise. Against this ERP, almost everything Odoo does that a sack plant needs is already present in some form; the real gaps are operator work instructions, photo/worksheet-style quality checks, ECO approval stages, a few equipment master-data fields, and freight landed on a run.

### Cited Findings

#### Evidence base and edition split
- The Odoo 19.0 Community tree has `mrp`, `mrp_account`, `mrp_landed_costs`, `mrp_product_expiry`, `mrp_repair`, `mrp_subcontracting` (+ `_account`, `_dropshipping`, `_landed_costs`, `_purchase`, `_repair`), `maintenance`, `stock_maintenance`, `repair`, and only the IoT framework stubs `iot_base`, `iot_drivers` (`installable: False`), `iot_box_image`. There is no `mrp_workorder`, `mrp_mps`, `quality*`, `mrp_plm`, `mrp_maintenance`, or `stock_barcode` module in it. — local clone of odoo/odoo branch 19.0 (head `042b6f9`, 2 Oct 2026), manifests in `scratchpad/odoo/src/addons/*/__manifest__.py`; e.g. [mrp manifest](https://github.com/odoo/odoo/blob/19.0/addons/mrp/__manifest__.py), [iot_drivers manifest](https://github.com/odoo/odoo/blob/19.0/addons/iot_drivers/__manifest__.py)

## 2. Which of these are new or materially changed in 19.0 compared with 18.0?

### Takeaway
Confirmed code-level changes (Community, from an 18.0 versus 19.0 source diff) are: operation cost modes, product-capacity-only work centres, work-order states driven by produced quantity, BoM batch size, production groups and multi-lot MOs, removal of worksheet fields and of company-level manufacturing lead time, MO-linked WIP entries, and small maintenance and repair model changes. For Enterprise apps only documentation changes are visible: Shop Floor, MPS (forecast suggestion), rescheduling modes and Quality control-point wording changed; PLM documentation is identical to 18.0.

## 4. What does Odoo 19 offer for in-house recycling of polypropylene waste into granules, and what does this ERP have?

### Takeaway
Odoo 19 has no recycling-specific feature; it would be modelled with ordinary BoMs, by-products, scrap locations and lot traceability, with no mass-balance, grading or contamination handling. This ERP already treats regrind as a first-class loop (cyclic BOM, by-product valuation, regrind percent in tape specifications, recovered-waste rules for virgin-only buyers), so adding a granulating step is mostly master data.

### Cited Findings
- The 19.0 manufacturing and repairs docs contain no mention of recycling PP, regrind, granules or polymer; the only "recycle" hit is the Repairs part type "Recycle" (return a salvaged part to stock). — grep of the local 19.0 docs clone; [repair_orders.rst](https://github.com/odoo/documentation/blob/19.0/content/applications/inventory_and_mrp/repairs/repair_orders.rst)
- Building blocks Odoo offers: by-products with cost share and "produced in operation"; a BoM that consumes a product and yields components (the "dismantle" pattern); flexible consumption; scrap to an Inventory Loss location with a loss account; MO real-cost overview; Production Analysis "Yield %"; OEE loss types "Process Defect" and "Reduced Yield"; lot/serial traceability. — [byproducts.rst](https://github.com/odoo/documentation/blob/19.0/content/applications/inventory_and_mrp/manufacturing/workflows/byproducts.rst), [dismantle_products.rst](https://github.com/odoo/documentation/blob/19.0/content/applications/inventory_and_mrp/manufacturing/workflows/dismantle_products.rst), [scrapped_inventory_valuation.rst](https://github.com/odoo/documentation/blob/19.0/content/applications/inventory_and_mrp/inventory/inventory_valuation/scrapped_inventory_valuation.rst), [production_analysis.rst](https://github.com/odoo/documentation/blob/19.0/content/applications/inventory_and_mrp/manufacturing/reporting/production_analysis.rst), [mrp_data.xml](https://github.com/odoo/odoo/blob/19.0/addons/mrp/data/mrp_data.xml)
- This ERP: the BOM graph is cyclic by design because "the regrind loop is real"; waste is a fraction of the input; by-products are valued at standard, share of run cost, or nothing. — [bom.py docstring](/home/user/hello-world/apps/manufacturing/bom.py)
- Tape specifications carry `regrind_item` and `regrind_percent`; recovered waste is recognised wherever it re-enters, and blocks a virgin-only buyer at order confirmation and shipment. — [woven.py L519](/home/user/hello-world/apps/manufacturing/woven.py), [compliance.py](/home/user/hello-world/apps/manufacturing/compliance.py)
- Waste is weighed at the machine and taken into stock against the run that made it. — [station_floor.py](/home/user/hello-world/apps/manufacturing/station_floor.py)
- The plant review says scrap sales to recyclers work through an ordinary invoice of the waste item that regrind puts into stock, "nobody has tried it"; incoming MFI and masterbatch tests are possible as inspection plans but none is set up. — [PLANT_REVIEW.md items 10-11](/home/user/hello-world/docs/PLANT_REVIEW.md)

### Inferences
- In-house recycling here would be one BOM (waste item in, granules out, with `waste_percent` for melt loss), a routing on a granulator work centre, and an inspection plan for MFI/ash/moisture; Odoo needs the same pieces and has no ready-made equivalent.
- Compliance walks recipes and lots through components that are by-products anywhere, so granules made from that waste should be recognised as recovered content (reading of `is_recovered`, untested); a purchased recycled granule would not be, unless it is marked some other way.
- Relevance: S (recycling starts after go-live); do not wait for Odoo-style features, none exist.

### Gaps
- No evidence found on how Odoo-based plants model polymer recycling (no official or partner example retrieved).
- The ERP's behaviour for waste grades (A/B/C regrind) and for waste bought from outside was not examined.
